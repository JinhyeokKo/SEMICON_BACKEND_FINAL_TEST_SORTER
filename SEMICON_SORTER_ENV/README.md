# 미쓰비시 환경 판정

GX Works2에서 작성한 환경 데이터 수신 및 허가 판정 로직이다. 실제 ESP32 센서 데이터는 **ESP32 → CIMON → MX OPC → GX Simulator** 순서로 전달되고, FX의 환경 판정 워드는 다시 CIMON을 거쳐 LS에 전달된다. 두 PLC의 직접 통신을 구현한 구성은 아니다.

## 주요 파일

| 파일 또는 폴더 | 용도 |
|---|---|
| `SEMICON_SORTER_ENV.gxw` | BL-001 원장에서 지정한 FX 프로젝트 |
| `SEMICON_SORTER_ENV_SIM.gxw` | 별도 시뮬레이션 작업 사본 |
| `workspacelist.xml` | GX Works2 작업 공간 메타데이터 |
| `MXOPC/MXConfigurator.mdb` | MX OPC 구성 데이터베이스 |
| `MXOPC/FXSIM2.spy` | DataSpy 작업 설정 |
| `FXtoESP_TEST/` | 이전 통신 검토 자료 |

기록된 환경은 **GX Works2 1.620W / GX Simulator / MX OPC Server 6.10**이다. 실제 기동에 사용하는 GXW와 OPC 구성은 [기준설정 기록](../06_TEST/README.md)으로 식별한다. 백업과 임시 DB를 현재 구성으로 혼용하지 않는다.

## 센서 데이터 적용

| 레지스터 | 역할 |
|---|---|
| `D200-D207` | 수신 준비 데이터 8워드 |
| `D208 / D209 / D210` | 준비 요청 ID / 적용 ID / 초기화 요청 |
| `D220-D227`, `D228` | 준비 스냅샷과 준비 완료 ID |
| `D230-D237`, `D238` | 적용 스냅샷과 적용 ACK |
| `D239`, `D257` | 초기화 ACK와 수신 ID high-water |
| `D240, D242, …, D254` | 값과 준비 ID를 포장한 DWORD 미리보기 8개 |

CIMON은 준비 ID와 같은 번호의 미리보기 8개가 일치한 뒤 적용을 요청하고 ACK를 확인한다. 준비값이 보인다는 이유만으로 환경 허가를 켜지 않는다. 센서 유효성, 상태, SEQ 및 AGE도 별도로 판단한다.

## 확정한 환경 기준

| 항목 | 기준 |
|---|---|
| 실측 입력 모드 | `M0=0` |
| 허가 유지 범위 | 18-30 °C / 30-70 %RH |
| 허가 복귀 범위 | 19-29 °C / 35-65 %RH |
| 정상 복귀 누적 | 새 정상 샘플 5회 |
| 타이머 | T0 K100=10초 / T1 K60=6초 |
| 경과시간 기준 | D7 < K120, 100 ms 단위로 12초 |
| 폴링 | MX OPC 500 ms / CIMON FX 그룹 500 ms / Deadband 0 |

FX의 환경 판정 송신 워드는 `D100=(D33×32)+(D34×2)+M100`이다. CIMON이 LS `D00400`에 전달하고 LS는 수신 확인과 신선도 감시를 거쳐 새 공정 시작 허가에 사용한다.

## 실행 시 확인

GX Simulator RUN, MX OPC 연결, CIMON FX 태그 읽기를 순서대로 확인한다. 환경 중계를 시작하고 FX·LS 자료 정상을 확인한 다음 센서 중계를 시작한다. 과거의 수동 입력 또는 모의 데이터만으로 실측 수신 완료를 판단하지 않는다. 실제 BOOT·SEQ와 적용 ACK가 전진하는지 확인한다.

한 PC에서의 동시 시뮬레이션 시험 중 간헐적인 OPC·중계 단절을 관측했다. 최종 기능 합격과 장기 통신 안정성 검증은 구분하며 원인을 특정 장치나 네트워크로 확정하지 않았다. 실제 판정 범위는 [완료보고서](../06_TEST/06_FINAL_PDF/SIM_COMPLETION_REPORT_R0_ko.pdf)를 참조한다.
