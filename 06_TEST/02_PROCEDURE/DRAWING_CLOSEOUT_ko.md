# 시뮬레이션 완료 범위의 도면 제출본 마감 가이드

작성일: 2026-10-15 / 대상: 사용자가 AutoCAD Electrical 2027에서 작성한 최종 DWG

이번 마감 범위는 현재 기능 도면 R100~R116의17장과 실물 확장 개념도 P101~P105의5장이다. 실물 PLC·컨베이어를 연결하거나 새 전기 상세도를 추가하는 단계가 아니다. 프로그램과 도면의 사실을 맞추고, 재시험 근거를 남긴 뒤 포트폴리오 제출 상태로 발행한다. ESP32/SEN0137의 실제 센서 시제품과 나머지 모사 기능은 구분한다.

이 문서는 도면 검토 체크리스트이며 사용자의 새 DWG를 이미 검사했다는 결과표가 아니다. 체크는 직접 확인한 뒤 채운다.

## 1. 작업 사본과 제출 기준을 고정한다

1. 현재22장 DWG·데이터 링크에 사용한 Excel·외부 이미지/글꼴 등 필요한 원본을 같은 개정의 작업 사본으로 보관한다. 기존 원본과 이전 PDF를 덮어쓰지 않는다.
2. LS·FX·CIMON·MX OPC·LabVIEW·ESP 성공본을 한 실행 기준으로 보관한다. 실제 파일명·저장일·버전을 시험 기록과 연결한다. 성공본을 새 예제로 교체하지 않는다.
3. 제목란에는 프로젝트명, 도면번호, 도면명, 개정, 실제 작성/검토일, 작성자, 발행상태를 같은 방식으로 넣는다. 작성/자체검토는 실제 한 사람의 이름과 실제 날짜를 쓴다.
4. 고객·발주처·검사기관의 실제 승인이 없으므로 고객승인/납품승인/안전인증 서명을 만들지 않는다. 기존 템플릿에 해당 칸이 있으면 공란 또는 ‘해당 없음 — 개인 포트폴리오’로 처리한다.

## 2. R/P를 기존002 도면번호와 연결한다

파일명은 기존 `002_PROCESS_FLOW_SYSTEM_ARCH.dwg` 방식으로 유지해도 된다. R/P ID는 이번 검토 자료의 추적용 ID이므로 임의로 지우기 전에 대응표를 작성한다. 같은 도면의 파일명·제목란·도면목록·교차참조·시험표에 동일한 최종 번호를 쓴다.

예를 들어 R101을 기존002번으로 배정했다면 아래처럼 적는다. 예시이며 기존002번을 반드시R101로 바꾸라는 지시가 아니다.

| 검토ID | 실제 도면번호 | 실제 파일명 | 실제 도면명 | 개정 |
|---|---|---|---|---|
| R101 | 002 | 002_PROCESS_FLOW_SYSTEM_ARCH.dwg | SYSTEM ROLES AND PROCESS SCOPE | R1 |
| R102 | 사용자가 배정 | 실제 파일명 | CURRENT COMMUNICATION NETWORK | R1 |

22개 검토ID가 각각 어느 최종 도면에 있는지 모두 추적되면 된다. 여러 기능을 한 시트에 합치거나 한 기능을 나누었다면 일대일 대응을 꾸미지 말고 `실제012/SHT01·SHT02`처럼 모두 적는다. 구도면에서 합쳐진 시트는 ‘폐기/통합’ 이력을 남기고 현재 목록에 중복하지 않는다.

## 3. 도면 공통 형식을 먼저 맞춘다

- 제목란·개정기호·페이지번호·전체도면목록·표 제목을 빠짐없이 맞춘다. 표 위 제목은 별도 TEXT로 넣어도 되고 TABLE 제목행으로 넣어도 된다. Excel A1 헤더부터 연결했다면 CAD 외부 제목이 간단하다.
- 온도°C, 습도%RH, 원시값×100, AGE100ms, timer100ms, 전압mV, 주기ms/s 등 단위를 값과 함께 적는다.
- LS와FX의 주소체계를 구분하고 각 도면에서 PLC/프로그램/태그의 소유자를 알 수 있게 한다. 예: LS D00100, FX D100.
- 화살표는 데이터/명령 방향과 대상이 분명해야 한다. CIMON중계 경로를 직접 PLC간 케이블로 바꾸지 않는다.
- 표의 주소·자료형·읽기/쓰기·스케일과 실제 DB/코드를 맞춘다. 추정한 값은 확정값처럼 적지 않는다.
- ‘다른 도면 참조’의 번호가 실제 존재하고, 구번호와 신번호가 섞이지 않는지 확인한다. 전기 개념도의 장치/단자/케이블 이름도 서로 맞춘다.

## 4. 아래22장 체크를 한 장씩 수행한다

한 장을 열고 내용을 확인한 뒤 실제 도면번호·검토일·수정내역을 기록한다. 표의 시험ID는 연결 가능한 근거다. 같은 실행이 여러 시험목적을 충족하면 증거를 재사용할 수 있으나, 실행하지 않은 조건까지 PASS로 복사하지 않는다. P도면은 기능시험 대상이 아니라 개념도 문서검토 대상이다.

## 5. R116에 실제 시험 근거를 채운다

시험기록은 절차서, 실행기록, 증거파일이 서로 연결되어야 한다. R116에는 모든 캡처를 억지로 넣기보다 요약을 적고 상세 시험기록표와 증거목록의 위치를 참조시킨다.

| 항목 | R116 또는 연결 증거목록에 적을 내용 |
|---|---|
| 시험ID/목적 | 예: P02 단발PASS / AE05 CSV·최근5건 |
| 실행ID/일시 | 같은 세션을 구분하는 실행ID, 실제 시작·종료시각, KST표기 |
| 적용 성공본 | LS/FX/CIMON/OPC/LabVIEW/ESP 파일·버전 식별 |
| 조건/실제값 | 실제설정·환경·요청ID·결과·누계차이·오류·지속시간 |
| 실제 결과 | NOT_RUN / PASS / FAIL / BLOCKED / N/A와 사유 |
| 증거 경로 | 제출묶음 안의 상대경로, 파일명, 필요하면CSV행번호·영상시각 |
| 도면 참조 | 실제 도면번호와 R/P검토ID의 대응 |
| 문제/재시험 | 발견문제ID, 이전실패기록, 수정범위, 재시험실행ID |
| 한계 | 모사범위, 미실시조건, 실물미시험, 알려진제약 |

PASS는 기대값을 적어 놓은 것이 아니라 실제 근거로 확인한 결과다. BLOCKED는 준비조건을 만들지 못해 시험을 못한 상태이지 합격이 아니다. 선택시험을 하지 않았다면 N/A/미실시와 사유를 남긴다. P101~P105는 ‘개념도 검토 / 실물시험 해당 없음’으로 남기고 P08의 가상안전시험을 실제안전합격으로 옮기지 않는다.

새 실행에서 정상·대표이상·복구·연속운전·정상종료의 근거를 확보한다. 단발PASS/FAIL/RETEST, 여섯 장치고장, 안전복귀, 환경·통신단절, CSV/화면 대응은 해당 절차를 따른다. 오래 걸리는 시험은 원래 시간을 기다리고 감시조건을 끄거나 타이머를 줄여서 합격시키지 않는다.

## 6. 발행 상태를 확정한다

| 대상 | 최종 표시 | 적용 조건 |
|---|---|---|
| R100~R116 | PORTFOLIO ISSUE — SIMULATION / SENSOR PROTOTYPE | 필수 기능시험 근거·실제설정·도면대조가 준비되고 확인한 범위를 명시한 뒤 |
| P101~P105 | CONCEPT / NOT FOR CONSTRUCTION | 항상 유지. 실물 설계·제작·시험을 완료한 것으로 바꾸지 않음 |

R도면의 이번확인 항목은 확인 후 ‘확인 필요’를 실제값·시험참조로 바꾼다. 기능정의 자체와 다른 미해결사항이 남았으면 해결·재시험 전까지 그 항목을 검증완료로 표시하지 않는다. 범위외 사항은 범위외라는 주석을 유지할 수 있다. 개념 P도면의 미확정 부하/치수/정격은 새 상세설계를 강제해서 메우기보다 ‘미정 — 개념범위’와 향후설계조건으로 남긴다.

개정번호는 문서관리 기준에 따라 일관되게 유지한다. 이번R1작업본을 최종마감한다면 모든R1파일의 내용·발행상태를 맞춰 보관한다. 시험 동결 뒤 기능/주소/조건이 바뀌면 새개정으로 관리하고 영향받는 도면·표·절차·시험을 함께 갱신한다. 사소한 글꼴/배치 수정이 제어기능 전체 재시험을 요구하는 것은 아니다.

## 7. A3 PDF로 출력해서 실제 읽기 상태를 검수한다

1. 각 DWG를 저장한다. 데이터링크표가 있다면 최종Excel을 확인하고 갱신 결과를 검사한다. 링크표를 갱신했는데 미저장인 상태로 발행하지 않는다.
2. 실제 사용한 플롯 장치/용지/플롯스타일/축척/방향을 기록한다. 보통 A3가로라면420×297mm, 기존제목란에 맞는 배치와 축척을 사용한다. 회사표준을 준수했다고 근거없이 표시하지 않는다.
3. Plot Preview에서 외곽선·제목란·표·그림·선·텍스트가 용지 안에 들어오는지 확인한다. 필요한CTB/STB는 이번프로젝트에서일관되게사용한다.
4. PDF를 다시 열어22장의 누락/중복/순서를 확인한다. 100% 또는 실제 A3 출력 크기에 가깝게 표·주소·주석을 읽어 보고, 크게 확대해야만 읽히는 글자는 수정한다.
5. 한글 깨짐/대체 글꼴·겹침·TABLE 행 잘림·너무 얇거나 두꺼운 선·화살표 방향·기호 누락·흑백 출력 시 구별 불가를 확인한다. 색상만으로 구분한 R/P·PASS/FAIL 정보는 문자도 남긴다.
6. PDF에서 잘못 보이는 부분은 DWG 원본에서 고쳐 다시 출력한다. PDF만 별도로 고쳐 DWG와 다르게 만들지 않는다.

## 8. 같은 개정의 원본·출력·근거를 함께 보관한다

최종 묶음에는 아래 자료가 서로 같은 개정을 가리키게 한다. 파일명 예시는 바꿔도 되지만 연결은 유지한다.

| 구분 | 보관 대상 |
|---|---|
| CAD 원본 | 실제 최종22장 DWG, 프로젝트파일을 사용했다면 그 파일, 필요한 종속파일·최종 표 원본 |
| 배포 도면 | 최종22장 PDF 또는 같은 순서의 합본PDF, 도면목록·개정·발행상태 포함 |
| 번호 대응 | R/P검토ID↔실제002형식도면번호·파일명 대응표 |
| 실행 기준 | 이번 시험에 사용한 코드/프로젝트/설정의 동결 사본과 버전 목록 |
| 시험 자료 | 절차서·실제 실행기록·증거목록·원본CSV·캡처/영상·알려진 문제/재시험 기록 |
| 제출 설명 | 시뮬레이터/실측 시제품/개념 설계 범위와 실물 PLC·컨베이어 미시험 한계 |

저장한 DWG를 다시 열고 PDF의 제목란 개정과 같은지 확인한다. 최종 제출 폴더의 다른 위치에서 열어도 필요한 표/그림이 누락되지 않는지 확인한다. 도면만이 아니라 사용한 Excel·외부참조가 필요하다면 함께 보관한다.

마감은 **현재 시뮬레이션·센서 시제품 범위를 증거와 함께 설명하는 제출본**을 완성하는 것이다. 추가 실물 구매·PLC 결선·컨베이어 시험·새 상세회로 작성은 이번 마감의 필수조건이 아니다.
